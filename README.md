# amirtaherin.github.io

Personal academic website of Amir Taherin, built with the [al-folio](https://github.com/alshedivat/al-folio) Jekyll theme.

**How publishing works:** every push to `main` triggers GitHub Actions
(`.github/workflows/deploy.yml`), which builds the site and deploys it to the `gh-pages`
branch. GitHub Pages serves `gh-pages`. **Nothing needs to be installed locally — ever.**
A build takes ~2–4 minutes; watch it under the repo's *Actions* tab. If a build fails,
the previous version stays live (nothing breaks publicly) — read the red run's log,
fix the file, push again.

## Two ways to edit

1. **In the browser (easiest):** open the file on github.com → pencil icon → edit →
   *Commit changes*. Works from any machine, even a phone.
2. **Locally:** edit files in this repo, then `git add -A && git commit -m "..." && git push`.

## What to edit for each change

| Change | File | Notes |
|---|---|---|
| Add news | new file in `_news/` | copy an existing announcement, change date + text |
| Add/edit publication | `_bibliography/papers.bib` | one BibTeX entry per paper; see fields below |
| Bio, education, positions | `_pages/about.md` | front matter controls sections; body is Markdown |
| Research buckets (projects) | `_projects/*.md` | one file per bucket; `importance` sets order; `{% cite key %}` pulls references |
| Student collaborators | `_pages/students.md` | |
| Reviewing service | `_pages/service.md` | |
| Profile photo | `assets/img/prof_pic.jpg` | replace the file, keep the name |
| CV PDF | `assets/pdf/AmirTaherin_CV.pdf` | replace the file; the CV nav item opens it directly |
| Email / links / IDs | `_data/socials.yml` | |
| Link color, small CSS | end of `assets/css/main.scss` | Persian Vivid Blue `#1c39bb` (light), `#7d90e5` (dark) |
| Favicon (the A logo) | `assets/img/icon.png` | referenced by `icon:` in `_config.yml` |
| Site title/description | `_config.yml` | |

## Publication entry cheat-sheet

```bibtex
@inproceedings{key2027name,
  abbr        = {VENUE},          % badge shown on the left
  bibtex_show = {true},           % show the Bib button
  selected    = {true},           % ONLY if it should appear on the homepage
  title       = {...},
  author      = {Last, First and Last, First},  % add * to names for equal contribution
  booktitle   = {Full Venue Name (ABBR)},       % journal = {...} for journals
  year        = {2027},
  additional_info = {To appear.}, % ONLY while not yet published; renders after the year
  doi         = {10.1145/...},    % once published
  arxiv       = {2701.01234},     % arXiv id -> arXiv button
  pdf         = {https://...},    % PDF button
  code        = {https://...},    % Code button
  abstract    = {...},            % powers the Abs toggle + the per-publication page
  annotation  = {* Equal contribution}
}
```
Every entry automatically gets its own page at `/publications/<key>/` (title links to it) —
**also create** `_pages/publications/<key>.md` by copying an existing one and changing the
key in both the front matter and the `{% bibliography -q @*[key=...] %}` line.
When a "to appear" paper is published: delete `additional_info`, add `doi`.

## Things not to touch

- `gh-pages` branch — machine-generated by Actions; never edit or merge it.
- `_layouts/about.liquid` and `_layouts/bib.liquid` — deliberate site overrides of the
  theme (socials by the portrait; project bullets; venue-year-then-"To appear" order;
  publication titles linking to detail pages). Edit carefully; a Liquid syntax error
  fails the build (safely).
- `Gemfile.lock` — pins the exact build toolchain; don't update casually.

## History / rollback

Old sites are preserved as branches: `old_2025_page` (Wowchemy site, pre-2026) and
`jekyll-2026` (minimal one-page Jekyll). Rolling back = point `main` at one of them and,
for `old_2025_page`/`jekyll-2026`, switch Pages source back to "main branch" in
Settings → Pages (the current site serves from `gh-pages` via Actions).
